# Design Notes

## Current implementation

The engine uses bitboards and a mailbox, FEN parsing and serialization,
deterministic Zobrist keys, reversible moves, legal move generation, generated
magic sliding attacks, UCI, classical evaluation, quiescence, PVS, iterative
deepening, a transposition table, move ordering, draw checks, and a fixed
position benchmark. A formal rating has not been established; reported match
results are recorded in `docs/ELO_LOG.md`.

Sliding attack multipliers are generated by `tools/gen_magics.cpp` with a fixed
PRNG seed. The generated constants live in `src/magic_numbers.h`; attack
tables are initialized once from those constants and then read-only. Move
legality stays easy to audit: generate pseudo-legal moves, make each candidate,
and reject it if its king remains attacked. The perft suite is the correctness
gate for this design.

## Design principles

- Follow the task scope agreed with the project owner.
- Prioritize correctness and small module interfaces.
- Avoid hidden mutable global state and dynamic allocation in the search hot
  path.
- Keep builds lightweight with `make -j2`.
- Keep evaluation options explicit, and use measured match results to choose
  their defaults.

## KingSafetyV2

`KingSafetyV2` is a UCI check option that defaults to `true`; set it to `false`
to restore the previous evaluator. It
adds middlegame-only terms for an uncastled king, the opponent's queen, lost
castling rights, open or semi-open nearby files, castling, an intact pawn
shield, and advanced shield pawns. These terms are grouped in
`params::KingSafetyV2Params` so later self-play tuning can adjust them in one
place. The false path calls the original evaluation terms only, preserving the
baseline benchmark signature of 47,626 nodes. The enabled default currently
produces 42,654 nodes at depth 6.

The automated evaluation checks compare five uncastled/castled FEN pairs and
two shield-pawn pairs. The documented minimum castling improvement is 40 cp;
the test output records the measured margins. This verifies direction and
basic effect size. The project owner reports a paired SPRT result of 810 games
at 5+0.05: 54.1% score, LLR 3.01, and H1 accepted. Castling occurred in 98% of
the enabled games and 16% of the disabled games. This supports the enabled
default; it is not an Elo estimate.

## Clock management

The UCI `Move Overhead` spin option defaults to 10 ms and accepts 0–5000 ms.
Each timed search subtracts this reserve before assigning soft and hard
budgets. The hard budget is the smaller of three times the soft allocation and
the remaining clock after the reserve. Hard-limit checks run every 8 nodes for
limits up to 50 ms, every 16 nodes up to 200 ms, every 32 nodes up to 1000 ms,
and every 256 nodes for longer limits. A clock at or below overhead plus 10 ms
uses only a depth-2 search, except when there is exactly one legal move, which
can be returned immediately. The search always completes depth 2 before
enforcing the hard limit; if a later iteration is interrupted, it returns the
best move from the last completed iteration. `tools/test_uci.py` checks both
sides at 50, 100, 150, 200, 300, and 500 ms with zero and 50 ms increments,
including a depth-2 info line, legal bestmove, and response before flag fall.
No SPRT was run for this clock-safety correction; the timing tests and fixed
benchmark do not measure playing strength.

## Build and verification

Makefile provides release and ASan/UBSan builds. `make test` checks 50 FEN
round-trips, malformed FEN rejection, make/unmake plus hash restoration,
generated magic attacks for every relevant occupancy, the KingSafetyV2
evaluation pairs, six perft positions, fixed tactical choices, UCI handshakes,
legal best moves, stop response, and repeatability of benchmark node counts.
`make bench` runs a fixed three-position suite at depth 6.

Search features (aspiration, check extension, SEE pruning, NMP, RFP, futility,
LMP, LMR, and IIR) default to enabled and can be disabled at compile time with
`BUBU_ENABLE_*` definitions. They have fixed-depth, tactical, and deterministic
node checks; none has a measured SPRT result yet.
