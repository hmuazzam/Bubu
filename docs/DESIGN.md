# Catatan Desain

## Current implementation

The engine currently has a bitboard plus mailbox position, FEN parsing and
serialization, deterministic Zobrist keys, reversible moves, legal move
generation, generated magic sliding attacks, UCI, a classical evaluator,
quiescence, PVS, iterative deepening, a transposition table, move ordering,
draw checks, and a fixed-position benchmark. Search strength has not been
measured in engine matches.

Sliding attack multipliers are generated by `tools/gen_magics.cpp` with a fixed
PRNG seed. The generated constants live in `src/magic_numbers.h`; attack tables
are initialized once from those constants and then read-only. Move legality is
kept easy to audit: generate pseudo-legal moves, make each candidate, and
reject it if its king remains attacked. This is intentionally simple while the
perft suite serves as the correctness gate.

## Prinsip

- Ikuti urutan task di Bagian 12 `PRD.md`.
- Utamakan korektness dan antarmuka modul yang kecil.
- Hindari state global mutable tersembunyi dan alokasi dinamis di hot path.
- Jaga build ringan dengan `make -j2`.

## Build

Makefile provides release and ASan/UBSan builds. `make test` checks 50 FEN
round-trips, malformed FEN rejection, make/unmake plus hash restoration,
generated magic attacks for every relevant occupancy, six perft positions,
fixed tactical choices, UCI handshakes, legal best moves, stop response, and
repeatability of benchmark node counts. `make bench` runs a fixed
three-position suite at depth 6.

Search features (aspiration, check extension, SEE pruning, NMP, RFP, futility,
LMP, LMR, and IIR) default to enabled and can be disabled at compile time with
`BUBU_ENABLE_*` definitions. They have fixed-depth, tactical, and deterministic
node checks; none has a measured SPRT result yet.
